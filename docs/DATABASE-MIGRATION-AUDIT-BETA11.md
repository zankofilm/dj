# ممیزی تعارض Migrationها – بتا ۱۱

## یافته‌های بحرانی
1. Migration شماره 000001 جدول `sellers` را می‌ساخت، اما Migration شماره 000009 دوباره همان جدول را ایجاد می‌کرد. این تعارض اجرای Migration را متوقف می‌کرد.
2. Migration شماره 000004 جدول `ledger_accounts` را با ساختار قدیمی ایجاد می‌کرد، اما Migration شماره 000013 دوباره همین جدول را با ساختار دفتر کل دوطرفه ایجاد می‌کرد. این تعارض نیز اجرای Migration را متوقف می‌کرد.

## اصلاحات
- Migration شماره 000009 اکنون جدول `sellers` موجود را گسترش می‌دهد و فقط `seller_documents` و `audit_logs` را ایجاد می‌کند.
- Migration شماره 000004 به slot بدون عملیات تبدیل شد؛ ساختار canonical دفتر کل فقط در Migration شماره 000013 ایجاد می‌شود.
- ابزار `scripts/check-migration-collisions.py` برای جلوگیری از تکرار `Schema::create` اضافه شد.

## نکته مهاجرت
این تغییرات برای خط نصب تازه و قبل از انتشار پایدار مناسب‌اند. اگر نسخه‌های قبلی روی دیتابیس واقعی اجرا شده باشند، نباید فایل‌های Migration اجراشده را بازنویسی کرد؛ باید Migration اصلاحی جدید و برنامه ارتقا با Backup طراحی شود. چون نسخه‌های فعلی بتا هستند و نصب عملیاتی تأیید نشده، این اصلاح در همین خط بتا اعمال شد.

## ریسک باقیمانده
- `owner_user_id` در این migration nullable است تا ارتقای داده‌های قدیمی شکست نخورد؛ جریان ثبت‌نام فروشنده باید قبل از فعال‌سازی فروشنده، مالک معتبر را الزام کند.
- بررسی کامل اجرای Migration روی MySQL واقعی هنوز انجام نشده است.
