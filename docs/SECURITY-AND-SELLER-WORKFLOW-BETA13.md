# اصلاحات امنیت پنل و گردش‌کار فروشنده – بتا ۱۳

## یافته‌های رفع‌شده
1. کنترلر درخواست فروشندگی به route با نام `seller.application.show` redirect می‌کرد، اما route متناظر تعریف نشده بود؛ GET status route اضافه شد.
2. ارسال درخواست فروشندگی محدودسازی نرخ نداشت؛ throttle روی POST درخواست فروشندگی اضافه شد.
3. دو درخواست هم‌زمان از یک کاربر می‌توانستند برای یک مالک، درخواست فروشندگی تکراری ایجاد کنند؛ بررسی درخواست موجود داخل تراکنش و با `lockForUpdate` انجام می‌شود.
4. امکان تعلیق آخرین مدیر کل فعال از مسیر مدیریت کاربران وجود داشت؛ کنترل محافظتی برای حفظ حداقل یک super-admin فعال اضافه شد.
5. جایگزینی مقادیر `.env` با `preg_replace` ممکن بود مقادیر دارای `$1` یا backslash را به‌عنوان backreference تفسیر کند؛ از callback امن استفاده شد.

## آزمون‌های ایستا
اسکریپت `scripts/check-beta13-regressions.py` وجود route، محدودسازی نرخ، قفل تراکنش، محافظت آخرین مدیر کل و callback امن را بررسی می‌کند.

## محدودیت‌ها
- `lockForUpdate` فقط در موتور و سطح ایزولیشن مناسب دیتابیس اثر هم‌زمانی مورد انتظار را می‌دهد؛ روی MySQL واقعی باید آزمون شود.
- آزمون Feature/HTTP و اجرای واقعی Laravel به Composer و `vendor` نیاز دارد.
- این مرحله جایگزین ممیزی جامع RBAC و آزمون نفوذ نیست.
