# ثبت‌نام موبایلی و تأیید پیامکی – بتا ۳۵

## تجربه کاربر
1. کاربر در `/register` شماره موبایل را وارد می‌کند.
2. شماره به قالب E.164 نرمال می‌شود؛ برای ایران `0912...` به `+98912...` تبدیل می‌شود. ارقام فارسی و عربی نیز پذیرفته می‌شوند.
3. برای شماره‌ای که قبلاً ثبت نشده، کد تصادفی ۶ رقمی ارسال می‌شود.
4. کاربر کد را در `/register/verify-code` تأیید می‌کند.
5. پس از تأیید، در `/register/complete` نام و گذرواژه را وارد می‌کند.
6. حساب با `phone_verified_at` و وضعیت `active` ساخته می‌شود و نشست کاربر آغاز می‌شود.

برای جلوگیری از افشای وجود حساب، پیام صفحه ارسال کد برای شماره‌های موجود و ناموجود از نظر متن یکسان است؛ شماره موجود کد دریافت نمی‌کند.

## مسیرها
- `GET /register`
- `POST /register/send-code`
- `GET /register/verify`
- `POST /register/verify-code`
- `POST /register/resend-code`
- `GET /register/complete`
- `POST /register/complete`
- `POST /login` – ورود با موبایل یا ایمیل و گذرواژه

## قرارداد OTP
- طول کد: ۶ رقم
- انقضا: ۳۰۰ ثانیه
- فاصله ارسال مجدد: ۶۰ ثانیه
- سقف ارسال: ۵ پیام در ساعت برای هر شماره
- سقف بررسی: ۵ تلاش برای هر کد
- کد خام در دیتابیس ذخیره نمی‌شود؛ فقط Hash نگهداری می‌شود.
- تأیید کد با تراکنش و `SELECT ... FOR UPDATE` انجام می‌شود تا استفاده هم‌زمان/مجدد محدود شود.
- رکوردهای قدیمی‌تر از یک روز هنگام درخواست کد جدید پاکسازی می‌شوند.
- درخواست‌های HTTP نیز با throttle محدود شده‌اند.

## قرارداد درگاه پیامک HTTP
درگاه موجود `App\\Services\\Sms\\SmsGateway` دو حالت دارد:
- `log`: فقط برای توسعه؛ در محیط production عمداً مسدود است.
- `http`: درخواست HTTPS با Bearer Token و JSON ارسال می‌کند.

تنظیمات در فایل `.env` هاست:
```dotenv
SMS_DRIVER=http
SMS_HTTP_ENDPOINT=https://YOUR-SMS-PROVIDER.example/api/messages
SMS_HTTP_TOKEN=YOUR_SECRET_TOKEN
SMS_SENDER=YOUR_SENDER_ID
SMS_TIMEOUT=10
```

بدنه JSON ارسالی:
```json
{
  "to": "+989121234567",
  "message": "کد تأیید بازارگاه: 123456\\nاعتبار: ۵ دقیقه",
  "sender": "YOUR_SENDER_ID"
}
```

سرویس مقصد باید پیام را بپذیرد و پاسخ HTTP موفق (۲xx) برگرداند. این یک قرارداد عمومی است؛ اگر پنل پیامکی شما API یا قالب درخواست متفاوتی دارد، باید Adapter همان ارائه‌دهنده اضافه شود. در این بسته هیچ حساب پیامکی یا اعتبار ارسال پیامک ارائه نشده است.

## نکات امنیتی و عملیاتی
- درگاه باید HTTPS باشد.
- توکن در `.env` نگهداری می‌شود، نه در کد یا دیتابیس.
- در محیط production از `SMS_DRIVER=log` استفاده نکنید.
- خطاهای Provider با متن عمومی به کاربر نشان داده می‌شوند؛ محتوای پاسخ Provider و کد OTP نباید در لاگ تولید ثبت شود.
- هاست باید امکان خروجی HTTPS به endpoint پیامک را داشته باشد.
- برای shared hosting بدون Terminal، متغیرها را با File Manager در `.env` تنظیم کنید و در صورت فعال بودن config cache، از پنل هاست آن را پاکسازی کنید یا از پشتیبانی هاست بخواهید.

## محدودیت‌های فعلی
- اتصال زنده به پنل پیامکی واقعی انجام نشده؛ endpoint/token باید از ارائه‌دهنده پیامک تهیه و تنظیم شود.
- قالب پیامک، sender و هزینه ارسال وابسته به قرارداد پنل پیامکی شماست.
- تست ارسال واقعی و تحویل اپراتوری بدون اعتبار و حساب پیامکی قابل تأیید نیست.
- تأیید ایمیل، ورود با OTP و بازیابی گذرواژه در این مرحله اضافه نشده‌اند.
