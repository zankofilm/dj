# تاریخچه، پیش‌نمایش، انتشار و بازگشت طراحی هوم‌پیج – بتا ۳۱

## مسیر پنل
`/admin/homepage-revisions`

مجوز: `homepage.manage`

## گردش کار
1. مدیر عنوان نسخه را وارد و «ذخیره و ساخت پیش‌نمایش» را انتخاب می‌کند.
2. برنامه از تنظیمات فعلی سه دامنه Snapshot می‌گیرد: نوارهای محصول، تنظیمات هویت سایت و بنرها.
3. پیش‌نمایش مدیریتی نسخه ساخته می‌شود و هیچ تنظیم زنده‌ای را تغییر نمی‌دهد.
4. مدیر برای انتشار باید چک‌باکس تأیید را فعال کند.
5. انتشار در یک تراکنش دیتابیس، تنظیمات Snapshot را روی جداول زنده اعمال می‌کند.
6. نسخه منتشرشده در تاریخچه باقی می‌ماند و قابل حذف نیست.
7. برای Rollback، مدیر نسخه منتشرشده قدیمی‌تر را باز و دوباره منتشر می‌کند.

## مدل داده
جدول `homepage_design_revisions`:
- title: عنوان قابل نمایش
- status: draft یا published
- snapshot: سند JSON شامل schema_version، captured_at، shelves، appearance و banners
- created_by و published_by
- published_at و timestamps

## دامنه Snapshot
- `homepage_shelf_settings`: عنوان‌های fa/ku/en، فعال بودن، تعداد، ترتیب و سرعت
- `site_appearance_settings`: برند، لوگو، نوار اطلاع‌رسانی، تماس و Footer
- `homepage_banners`: متن‌های سه‌زبانه، مسیر تصویر، لینک، ترتیب و بازه نمایش

## امنیت و یکپارچگی
- کنترل مجوز در مسیر و کنترلر
- CSRF برای عملیات تغییردهنده
- تأیید صریح پیش از انتشار
- قفل رکورد نسخه و تراکنش هنگام اعمال
- اعتبارسنجی ساختار Snapshot و محدودسازی مقادیر عددی
- ثبت ایجاد، انتشار و حذف در AuditLog
- نسخه منتشرشده قابل حذف نیست

## محدودیت شفاف
پیش‌نمایش این بتا یک نمای مدیریتی از محتوای Snapshot است؛ هنوز رندر کامل storefront واقعی در حالت preview و بدون اثرگذاری بر کاربران عمومی پیاده‌سازی نشده است. Snapshot از وضعیت فعلی می‌گیرد؛ ویرایش بصری محتوا داخل خود پیش‌نویس هنوز در این مرحله نیست. تغییرات واقعی در صفحه تنظیمات بنر، نوارها و هویت سایت انجام می‌شوند و سپس از آن وضعیت نسخه ذخیره می‌شود.

## Migration
Migration شماره `000020` جدول تاریخچه طراحی را ایجاد می‌کند. اجرای آن روی MySQL هاست اشتراکی هنوز در محیط واقعی تأیید نشده است.
