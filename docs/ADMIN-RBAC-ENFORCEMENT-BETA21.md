# اجرای مجوزهای پنل مدیریت – بتا ۲۱

## هدف
مجوزهای تعریف‌شده در AccessControlSeeder از حالت صرفاً داده‌ای خارج شده و در مرز HTTP پنل مدیریت اعمال می‌شوند.

## قرارداد
- Middleware با نام `permission` در bootstrap ثبت می‌شود.
- قالب استفاده: `permission:<permission-key>`
- کاربر احراز هویت‌نشده پاسخ 401 دریافت می‌کند.
- کاربر غیرفعال پاسخ 403 می‌گیرد.
- کاربر فاقد مجوز پاسخ 403 می‌گیرد.
- نقش super-admin از طریق مجوزهای seed شده دسترسی مدیریتی را می‌گیرد.

## نگاشت مسیرها
| مسیر | مجوز |
|---|---|
| تمام پنل مدیریت | `admin.access` |
| داشبورد | `admin.dashboard.view` |
| کاربران | `users.manage` |
| کاتالوگ | `catalog.manage` |
| بررسی فروشندگان | `sellers.review` |

## اصول امنیتی
مخفی‌کردن لینک در رابط کاربری جایگزین کنترل سمت سرور نیست. کنترل مجوز روی هر Route اجرا می‌شود. مجوزهای مالی، انتشار قالب و افزونه در مسیرهای آینده باید با کلیدهای مستقل اعمال شوند؛ وجود کلید در Seeder به‌تنهایی به معنی اعمال آن نیست.

## آزمون و محدودیت
` scripts/check-beta21-admin-permissions.py ` قراردادهای ایستا را بررسی می‌کند. آزمون HTTP واقعی با نقش‌های متفاوت، نشست Laravel و MySQL هنوز اجرا نشده؛ برای آن محیط دارای vendor و دیتابیس لازم است.
