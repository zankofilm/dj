# راهنمای استقرار بازارگاه روی هاست اشتراکی بدون Terminal

## هدف انتشار
کاربر باید فقط از File Manager، پنل ساخت دیتابیس و مرورگر استفاده کند؛ هیچ دستور SSH، Terminal، Artisan یا Composer نباید برای نصب اولیه لازم باشد.

## ساختار استقرار مورد انتظار
- فایل‌های برنامه در ریشه خصوصی برنامه قرار می‌گیرند.
- ورودی وب فقط از مسیر `public/` سرو می‌شود.
- فایل `.env`، پوشه‌های `app/`، `bootstrap/`، `config/`، `database/`، `storage/` و `vendor/` نباید مستقیماً از وب قابل دریافت باشند.
- اگر میزبان اجازه دهد، بهترین چیدمان این است که هسته برنامه خارج از `public_html` و فقط محتویات `public/` داخل `public_html` قرار گیرد.
- در میزبان‌هایی که این چیدمان را پشتیبانی نمی‌کنند، قواعد `.htaccess` باید قبل از انتشار بررسی شوند؛ نبود یا غیرفعال بودن mod_rewrite یک مانع انتشار است.

## روند نصب برای کاربر
1. در پنل هاست یک MySQL Database و Database User بسازید و دسترسی کامل آن کاربر به همان دیتابیس را بدهید.
2. ZIP انتشار کامل را از File Manager در محل تعیین‌شده بارگذاری و Extract کنید.
3. دامنه را به پوشه `public` متصل کنید؛ اگر امکان Document Root مستقل نیست، از چیدمان تأییدشده بسته استفاده کنید.
4. آدرس `https://دامنه/setup.php` را باز کنید.
5. فقط وقتی تمام بررسی‌ها سبز هستند، اطلاعات دیتابیس و مدیر را وارد کنید.
6. پس از نصب، وجود قفل نصب و غیرفعال‌شدن Setup را کنترل کنید.

## قواعد بسته انتشار
- ZIP نهایی باید `vendor/autoload.php` و کد Laravel متناظر با `composer.lock` را از پیش داشته باشد.
- وابستگی‌های توسعه مانند PHPUnit، Pint و Faker نباید در بسته Production قرار گیرند.
- فایل `composer.lock` باید همراه ساخت Release نگهداری شود.
- هیچ مرحله نصب نباید نیازمند اجرای Composer روی هاست مشتری باشد.
- بسته باید با PHP 8.2+ و MySQL سازگار با Laravel 12 در محیط هدف آزمون شود.

## نکته وضعیت فعلی
نسخه بتا ۱۶ هنوز `vendor` ندارد؛ بنابراین این ZIP صرفاً بسته سورس توسعه است و نباید به‌عنوان بسته نصب کامل روی هاست استفاده شود. بررسی‌های Setup در این نسخه خطاهای محیط هاست و ناقص بودن بسته را شفاف‌تر نشان می‌دهند، اما وابستگی‌های Composer را تولید نمی‌کنند.
