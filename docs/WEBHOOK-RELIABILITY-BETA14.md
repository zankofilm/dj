# قابلیت اطمینان Webhook – بتا ۱۴

## پرداخت
- شناسه رویداد و مرجع پرداخت اعتبارسنجی و محدود می‌شوند.
- رویداد با کلید یکتای `(provider_key, provider_event_id)` ثبت می‌شود.
- در برخورد درج هم‌زمان، رکورد canonical دوباره خوانده می‌شود.
- بازپخش شناسه رویداد با payload hash یا مرجع پرداخت متفاوت با HTTP 409 رد می‌شود.
- Claim پردازش با قفل سطری و وضعیت `processing` انجام می‌شود.
- رویداد پردازش‌شده پاسخ 200 و رویداد در حال پردازش پاسخ 202 با Retry-After می‌گیرد.
- مرجع پرداخت برای تطبیق و ممیزی در جدول رویداد ذخیره می‌شود.

## حمل
- callback دیررس نمی‌تواند وضعیت نهایی delivered، returned_to_sender یا cancelled را عقب ببرد.
- رویداد دیررس ثبت می‌شود اما وضعیت جاری مرسوله حفظ می‌شود.

## ریسک‌های باقیمانده
- رویداد `processing` پس از توقف ناگهانی ممکن است نیازمند بازیابی دستی باشد؛ Job بازیابی lease منقضی باید اضافه شود.
- آزمون واقعی MySQL و Sandbox درگاه/شرکت حمل در این محیط انجام نشده است.
- این مرحله بررسی ایستا است و جایگزین آزمون نفوذ یا تأیید امضای Provider واقعی نیست.
