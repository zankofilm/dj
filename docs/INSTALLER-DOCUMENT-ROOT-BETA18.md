# دسترسی نصب‌کننده در هر دو حالت Document Root – بتا ۱۸

## مشکل رفع‌شده
در نسخه قبلی، راهنمای استقرار حالت پیشنهادی را Document Root روی `public/` معرفی می‌کرد، اما فایل نصب‌کننده فقط در ریشه بسته (`setup.php`) قرار داشت. در این حالت مسیر `/setup.php` در دامنه به `public/setup.php` نگاشت می‌شود و فایل نصب‌کننده پیدا نمی‌شد.

## راه‌حل
فایل `public/setup.php` به‌عنوان ورودی عمومی کوچک اضافه شده است و نصب‌کننده اصلی را از ریشه بسته فراخوانی می‌کند. چون فایل اصلی با `require` اجرا می‌شود، `__DIR__` و مسیرهای خصوصی آن همچنان به ریشه بسته اشاره می‌کنند.

## دو حالت
- Document Root روی ریشه بسته: `/setup.php` به نصب‌کننده اصلی می‌رسد.
- Document Root روی پوشه `public`: `/setup.php` به `public/setup.php` می‌رسد و نصب‌کننده اصلی را اجرا می‌کند.

## کنترل‌های لازم روی هاست
- مسیر `public/setup.php` باید قابل اجرا باشد.
- پوشه اصلی برنامه باید بیرون از فضای عمومی باقی بماند یا دسترسی مستقیم آن مسدود شود.
- پس از نصب، قفل `storage/app/installed.lock` باعث پاسخ 404 از نصب‌کننده اصلی می‌شود.
- پس از اتمام نصب، حذف فیزیکی هر دو فایل setup از File Manager توصیه می‌شود؛ قفل نصب همچنان دفاع دوم باقی می‌ماند.

## محدودیت فعلی
این اصلاح فقط دسترسی نصب‌کننده را در دو چیدمان برقرار می‌کند. بسته هنوز فاقد `vendor/` و `composer.lock` است و تا ساخت Release کامل، نصب عملیاتی امکان‌پذیر نیست.
